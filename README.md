# 游戏资料库（web）

单款游戏的中文人物、地点、势力资料库。公开只读网站 + 唯一拥有者管理后台，全部内容为纯文字（受限 Markdown + 内部链接），无图片、无社区功能。

## 功能

- 三类实体：人物、地点、势力
- 人物专属字段：种族、所属势力（多值带角色/备注）、人际关系（有向双向称呼）、分级（主要人物 / 次要人物 / 背景人物，可留空；仅在后台与导出保留，列表页不展示）
- 人物列表：附"相关资料"计数列（任务出场 + 整篇关联 + 相关段落，简单相加）
- 地点/势力层级：单父树结构，父级面包屑与下级列表
- 地点辖区：地点可标注归属势力（单值引用，可留空）；结构总览页地点树逐层按辖区分区（势力名拼音序，未标注末位）
- 结构总览页（`/tree`）：地点与势力层级树一览；兄弟组按展示规模降序、同规模拼音兜底；"单链至叶"压缩为链行（`A — B`）；结构节点可折叠（默认展开）；草稿节点剔除，其已发布后代挂靠最近已发布祖先
- 势力类型：封闭四类枚举（国家/政权、企业/商社、帮派/佣兵、组织/机构，可留空）——本体标注，与层级无关；树页"独立势力"分区（顶层无子级者）按类型分组
- 灵活文本条目：来源类别 / 来源名称 / 游戏内定位
- 受限 Markdown：标题、段落、列表、引用、粗斜体；禁止 HTML、图片、表格、外部链接
- 内部链接：`[[实体名]]`、`[[实体名|显示文字]]`、`[[文本:标题]]`、`[[文本:标题|显示文字]]`
- 段落级实体关联（内联解析 + 手动关联 + 批量关联）
- 整篇级关联：标记整篇文本与实体相关，实体页以"长篇资料"区折叠展示
- 草稿 / 已发布状态，公开页面只显示已发布内容
- 实体名称与别名搜索
- 同名互链：实体详情页"参见"行列出名称池（标准名+别名）相交的其他已发布实体（跨/同类型），格式"标准名（类型）"
- 单一拥有者登录（环境变量凭据 + 签名会话 Cookie）
- JSON 全量导出（含种族、势力关联、关系、层级与整篇级关联）

## 技术栈

- Next.js 16（App Router，Turbopack）
- SQLite（better-sqlite3）是唯一数据后端；站点构建为纯静态发布（见 `DEPLOY.md`）
- jose 签名会话、markdown-it 受限渲染

## 本地运行

```bash
npm install
npm run seed                 # 写入虚构测试数据（清空并重建，仅用于可弃数据）
npm run dev                  # http://localhost:3000
```

默认登录：用户名 `admin`，密码 `admin`（无环境变量时的本地回退值，见 `lib/auth-core.ts`；生产环境必须设置 `ADMIN_PASSWORD` 与 `AUTH_SECRET`）。

## 内容格式

正文使用受限 Markdown：

```markdown
## 标题

普通段落，**粗体**、*斜体*、- 列表项、> 引用。

他提到了[[沈砚|那个穿黑衣服的人]]。

更多信息见[[文本:白潮港的测潮记录|测潮记录]]。
```

规则：

- 空行 = 新段落；单个换行保留
- 实体链接目标按标准名称或别名解析，目标是稳定记录，改名不破坏链接
- 显示文字可以是原文中的模糊指代（不要求是别名）
- 同类实体的标准名必须唯一（人物/地点/势力各自内部查重）；跨类型同名、名称与别名重合是允许的
- 名称解析到多个实体时，用钉定写法指定目标：`[[名称@slug]]`、`[[名称@slug|显示文字]]`、文本类 `[[文本:标题@slug]]`（slug 见后台候选提示），钉定不改变显示文字
- 未解析 / 有歧义的链接在管理后台提示，公开页面不显示坏链接

## 数据模型

- `entities`：人物 / 地点 / 势力（slug、名称、别名、简介、说明、种族、上级引用、人物分级、状态）；同类标准名由部分唯一索引兜底
- `entity_aliases`：实体别名
- `entity_factions`：人物所属势力关联（带角色/备注与序号）
- `person_relations`：人物↔人物有向关系（正向与反向称呼、备注）
- `text_entries`：文本条目（标题、来源、定位、正文、状态）
- `text_blocks`：按空行拆分的段落块
- `content_links`：文本块到实体 / 文本的关联（内联或手动）
- `text_entity_associations`：整篇级关联（文本条目↔实体）

## 目录结构

```
app/                     # 路由（公开 + admin）
  admin/(protected)/     # 需要登录的后台
  entities/ texts/ search/ tree/
components/              # Header 与后台表单
lib/
  db/                    # store 接口 + SQLite 实现 + 类型（supabase.ts 仅历史留档）
  markdown.ts            # 受限 Markdown + [[...]] 解析
  render.ts              # 带链接解析的渲染辅助
  links.ts               # 链接问题检查
  auth.ts / auth-core.ts # 会话与登录
scripts/                 # seed.ts、verify-data.ts 等
supabase/                # 仅历史留档，可忽略
proxy.ts                 # /admin 路由保护
```

## 部署

现行部署为本地构建纯静态站点后上传 Cloudflare Pages，详见 `DEPLOY.md`。早期的 Vercel + Supabase 服务器模式已弃用，`lib/db/supabase.ts` 与 `supabase/` 仅作历史留档。

## 测试数据

虚构样例直接内置于 `scripts/seed.ts`；`npm run seed` 会**清空目标库并写入虚构数据**，默认目标 `data/app.db` 即真实生产数据——仅可对可弃库执行，勿对真实数据运行。
